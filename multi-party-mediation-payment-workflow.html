What is a multi-party mediation workflow?

A multi-party mediation workflow keeps one scheduled matter connected to multiple clients, billing contacts, and participants. TexMediator uses the booking and intake information to send separate Stripe payment requests automatically to billing clients and deliver Zoom access to participants for the same mediation session.

The Business Problem

One appointment did not mean one payer.

A conventional checkout flow assumes one customer is paying for one transaction. Mediation can be different: multiple law firms or parties may be responsible for separate shares of the same scheduled service.

The appointment had to stay unified

The mediation itself still needed one date, one time, one matter, one intake process, and one set of scheduling details. Creating a second appointment just to collect another payment would fragment the operational record.

Each billing client needed a separate payment request

The workflow needed to identify the billing contacts for multiple clients and send the appropriate payment request to each, while keeping every payment connected to the same mediation.

Manual invoice creation added avoidable work

Re-entering names, email addresses, appointment details, and payment amounts after every qualifying booking would create repetitive work and another opportunity for information to be copied incorrectly.

System Architecture

How the payment and Zoom workflow works

The workflow reuses scheduling and intake information to send each billing client the appropriate Stripe payment request and provide participants with Zoom access.

1. Schedule the mediation

An attorney selects the mediation service, date, and time through the scheduling experience. The appointment becomes the central record for the workflow.

2. Collect structured intake data

The scheduling form collects case details, client billing contacts, and participant contact information for payment requests and Zoom access.

3. Receive the scheduling event

When a qualifying appointment is scheduled, Acuity sends a signed webhook to the server-side integration. The endpoint verifies the request before processing the booking data.

4. Identify the clients and participants

The integration reads the appointment and intake data to identify billing clients and participants, then applies the workflow rules for the selected mediation type.

5. Send automatic Stripe payment requests

The server-side integration uses Stripe to create and send separate invoices to the billing clients for their respective mediation fees. Each client receives a payment request automatically.

6. Deliver Zoom access to participants

Participants automatically receive the Zoom joining information for the shared mediation. The appointment, separate client payment requests, and meeting access remain part of one coordinated process.

Data Flow

One booking, coordinated payments and meeting access

Mediation booking and intake provide the client and participant details used by the automation. Stripe sends separate payment requests to billing clients, and participants receive Zoom access for the shared session.

Component Role in the workflow
Custom website Gives the client a branded path into the mediation information, pricing, policies, and booking experience.
Acuity Scheduling Holds the appointment and structured intake information used by the automation.
Webhook Notifies the server-side integration when the relevant scheduling event occurs.
Server-side function Verifies the event, reads the appointment data, applies the business rules, and calls the payment system without exposing private API credentials in browser code.
Stripe Creates and sends separate invoices and payment requests to the billing clients.
Zoom Provides the shared virtual mediation session. The connected workflow automatically delivers joining information to participants.

The Important Part

The integration is more than connecting two APIs.

The useful part of workflow automation is translating a real business process into explicit rules: when something should happen, which data it should use, and what should happen when required information is missing.

Trigger only on the right event

The automation should respond to the intended scheduling event rather than creating invoices from unrelated page views, form visits, or browser-side actions.

Use the booking as the source of truth

Client billing and participant contact information is collected during booking, so payment requests and Zoom access can use the details associated with the same appointment.

Keep sensitive credentials server-side

Payment credentials and webhook validation belong in server-side code. The public website can start the customer journey without exposing private integration secrets to the browser.

Why Automate It

What the workflow removes from the mediator's day

The purpose was not automation for its own sake. It was to remove a repetitive handoff from a real professional-service workflow.

Less duplicate data entry

Information already supplied during scheduling can be reused by the billing workflow instead of being typed into another system again.

Clearer payment responsibility

Each party can receive the payment request intended for that party without turning one law firm into the default payer for the entire mediation.

A more connected client experience

Scheduling, case intake, confirmation, video-meeting information, and payment steps operate as parts of one designed process rather than as unrelated tools the mediator has to coordinate manually.

Frequently Asked Questions

Multi-party mediation workflow FAQ

Can more than two clients receive separate payment requests?

Yes. TexMediator supports multiple clients within one scheduled mediation, with separate Stripe payment requests sent automatically to the billing clients.

How are the Stripe payment requests created?

The booking captures client billing information. A scheduling webhook triggers server-side logic, which reads the appointment data and uses Stripe to create and send the appropriate invoices.

Does the mediator create each invoice manually?

No. Once the required booking and billing information is present, the integration creates and sends the client payment requests automatically.

What technology is used?

The implementation combines a custom website, Acuity Scheduling intake data, a signed scheduling webhook, server-side automation, Stripe invoicing, and Zoom meeting access.

Do participants receive Zoom access automatically?

Yes. Participants receive Zoom joining information automatically for the shared mediation session, using the contact details supplied during scheduling and intake.

Can this workflow be adapted for another business?

Yes. The same event-driven pattern can support other businesses where a booking or form submission needs to trigger participant-specific billing, notifications, records, or internal actions.
